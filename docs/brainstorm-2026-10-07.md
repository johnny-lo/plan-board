## 已定（使用者選的）

1. 決定卡片和 Thoth **不合併**（Thoth 管「派出去的工作有沒有真的做完、有證據」；卡片管「等你拍板的問題」；Thoth 是公開產品）。
2. 範圍變動的規則：**大的改動先經過使用者**，小的調整照常做但一定記錄（選項 2，不是「只記錄」也不是「全部都要核准」）。
3. 做法 **A**：計畫存在每個 repo 裡（跟 git 走，三台 Windows／Linux 電腦都一樣），用 Claude Code mod 顯示。不用 Linear（Orca 只內建 Linear、沒有 Jira；這台 Orca 沒接 Linear），不用 Orca 的看板（Orca 看板的卡片是 worktree，放不了「之後」的項目與變動原因）。
4. 手機**幾乎不重要**（手機上多半是輕量下指令）。
5. **兩層**：
   - **項目**（使用者的層級，用使用者的話）：新增、拆開、刪掉、改目標要使用者點頭；數量少、變動少。
   - **步驟**（指揮官的層級）：怎麼切、派給誰、做到哪；可以隨時調整、不用問，但每次變動自動記錄；平常收起來。
   - 例：Thoth 的 SETUP-1／2／3、MOD-1b／1c、小修批次，對使用者來說都只是某個項目底下的步驟。
6. 決定卡片要帶**前因後果**（取代為了做決定而另做的 HTML 頁）：標明屬於哪個項目、排第幾、之前發生了什麼；選了就生效、寫回計畫。
7. **公開**：自己的公開 repo，和 Thoth 分開；用 Thoth 的人可選裝。（使用者選「一開始就公開」，不是「先自己用」。）

## 設計第 1 段（使用者已同意）

- 一個新的 Claude Code 插件，取代現在 Legion 上的決定卡片 mod（`~/.claude/mods/decisions`，舊卡片要搬過來）。
- 一個窗格兩個分頁：**總表**（項目一句話、照順序、做完／進行中／下一個／之後；點開看步驟與變動紀錄）、**等你決定**（卡片帶項目與前因後果，選了就生效）。輸入框上方一列「計畫：2 項進行中 · 1 個決定等你」，按了開窗格。
- 資料存在 repo 裡的計畫資料夾，跟著 git 走（現在的決定卡片只存在一台電腦的 Claude Code 設定裡）。
- 一個 repo 一份計畫；大 feature 是一個項目，需要時可分階段。
- 平常由 AI 更新，**只能透過插件給的工具改**，每次變動一定留下紀錄（不靠 AI 記得）。

## 設計第 2 段（使用者已同意）：總表與變動紀錄

- **規則**：項目層的改動要使用者點頭（AI 只能提案，提案自動變決定卡）：新增、刪掉、拆開／合併、改一句話或目標、改順序。步驟層的改動（新增、拆開、刪掉、改派、狀態）不用問，但一定記錄。
- **做完不用點頭**（使用者：「有證據鏈以後，理論上就不用我判斷是不是做完吧」）：
  - **外掛只做顯示，不自己讀 Thoth**（使用者：「我要的是 AI 自己更新這個外掛看板？外掛只做顯示」）。步驟走 Thoth 時，由 AI 用它自己的 Thoth 工具看到 `pass`，再用外掛的工具把步驟標做完、填上證據來源（Thoth 任務 id）。外掛因此完全不依賴 Thoth。
  - 步驟沒走 Thoth → **先相信** AI 標的做完（使用者：「先相信好了，如果沒有跨供應商的其實他們自己理論上就有這種一套系統吧」）。總表不加警告；紀錄寫明來源是「AI 回報」還是「Thoth pass（任務 id）」。
  - 項目的狀態是顯示時從步驟算出來的：全部步驟做完 → 做完；有步驟在做 → 進行中。
- **項目**：一句話（使用者的話）＋一行「做完的樣子」。狀態：做完／進行中／下一個／之後。「下一個」不存（照順序第一個還沒開始的）；有步驟開始就自動「進行中」。刪掉的項目從總表消失、紀錄保留。
- **步驟**：一句話＋狀態（還沒開始／進行中／做完／卡住，卡住連到在等的決定卡）＋可選的 Thoth 任務 id。
- **變動紀錄**：每個項目一串，新的在上，只能加。每筆：時間、層級、改了什麼（前→後）、原因（必填一句）、來源（AI／使用者在卡片 #id 選的／直接改檔被發現／Thoth pass）。

## 設計第 3 段（使用者已同意）：決定卡片

- 卡片內容：問題（一行）、位置（項目、排第幾、卡在哪個步驟；AI 給項目和步驟，外掛補其餘）、為什麼現在問（AI 寫 1–2 句，必填）、之前發生了什麼（外掛顯示時從該項目的變動紀錄抓最近幾筆）、選項（每個附一句「選了會怎樣」，最多一個標「建議」附理由）、想法輸入框。
- **外掛只做顯示，沒有例外**（使用者選的）：提案卡選「同意」也是送給 AI，由 AI 用工具改計畫；外掛不自己改。整份計畫只有 AI 透過工具這一個寫入者。
- 選項和想法照現在的機制送給 AI（blocking 立刻送，其他批次）。結案時「決定了什麼」必填，寫進項目的紀錄。
- 觀察（這次 session 自己用的時候）：卡片放不下前因後果時只能寫「詳見對話」；使用者兩次都用「想法」回答而不是選選項，所以想法要當主要回答方式設計。
- 卡片多的時候：最上面那張全部攤開，其他只露問題和位置，點了才展開（使用者選的）。

## 設計第 4 段（使用者已同意）：AI 的工具

- **讀**：沒有讀取工具。外掛每輪把計畫摘要（所有項目、進行中項目的步驟、未決定的卡片）附進提示，跟現在 decisions mod 的 `prompt.compose` 一樣。
- **寫**（每個工具自動寫紀錄，原因必填）：
  - `propose_change`：項目層改動（新增、刪掉、拆開／合併、改目標、改順序）→ 顯示成提案卡，選項固定「同意／不要」＋想法。
  - `apply_change`：必須帶一張使用者選了「同意」的提案卡編號，否則拒絕；套用的就是提案的內容。使用者在想法裡改了內容 → AI 重新提案。（這是工具驗證輸入，不是外掛自己動手。）
  - `update_step`：步驟的新增、拆開、刪掉、改派、狀態；標做完要帶證據來源（Thoth 任務 id，或 AI 一句結果）。
  - `add_decision`／`resolve_decision`：沿用，加上項目、步驟、為什麼現在問、選項後果、建議；結案的「決定了什麼」必填。
- **直接改檔**：
  - 擋：有裝外掛的 session 裡，Edit／Write 改計畫資料夾會被擋下並提示改用工具（mod 的 `tool.call` 攔得到內建工具）。
  - 抓：每次工具寫入時在紀錄裡存計畫內容的指紋，外掛顯示時比對；對不上 = 有人繞過工具。指紋跟 git 走，別台電腦用工具改再 pull 過來不會誤報。
  - 抓到：窗格上方顯示「計畫被直接改過」並告訴 AI；AI 看 git diff 補一筆紀錄（來源：直接改檔被發現）。**改到項目層 → AI 開卡問使用者留下還是還原**（使用者選的，照建議）。

## 設計第 5 段（使用者已同意）：檔案放哪裡、多台電腦同時改

- **跟程式碼放一起，每個分支各一份**（使用者選的；沒選「專用 plan 分支」的建議）。後果：每個 worktree 的窗格顯示那個分支知道的計畫；feature 分支上的進度，要合併後主分支才看得到。外掛改成以 worktree 的根目錄（`git rev-parse --show-toplevel`）找計畫，不再用 git common dir 讓所有 worktree 共用。
- **格式**：整份計畫只存一串只能往後加的紀錄（每行一筆 JSON），總表和卡片都從紀錄算出來，不另存狀態。按了沒送的選擇和想法屬於這台電腦，照舊存在 `$.store`（以 worktree 路徑分開）。
- **合併**：`.gitattributes` 對紀錄檔設 `merge=union`，兩個分支或兩台電腦各自加的紀錄 git 會直接合在一起不衝突；算總表時依時間排、以紀錄 id 去重。
- **第 4 段的指紋要改**：整份計畫的指紋在合併後一定對不上（會誤報），改成**每筆紀錄各自帶檢查碼**。被改過的舊紀錄、手寫的新紀錄對不上；從別的分支合進來的紀錄檢查碼是對的，不會誤報。「擋 Edit／Write」保留（計畫檔在 worktree 裡，Thoth 派出去的人碰得到）。
- **commit**：工具只寫檔案、不自己 commit；計畫的改動跟著 AI 平常的 commit 走，推到 GitHub 也一樣（公開 repo 的計畫就會公開，跟其他文件一樣）。
- 位置暫定 repo 根目錄 `plan/`。
